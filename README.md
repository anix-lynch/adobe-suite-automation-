# Adobe Suite Automation — E-commerce Campaign Case Study

![Demo](demo.gif)

🔗 **GitHub:** https://github.com/anix-lynch/adobe-suite-automation-

Portable production case study proving: source assets → scriptable recipes →
real Adobe app working files → real final exports. Built as a testable,
end-to-end demonstration of programmatic Adobe Creative Suite production —
not a mockup, not a generated-image demo. Every deliverable in
`03_final_exports/` was produced by a real script driving a real Adobe app
(Photoshop, Illustrator, After Effects, Premiere Pro), verified on disk.

Brand: **Luna Retail** — a fictional brand invented for this kit. Not a real
company, not built for or affiliated with any real employer.

## The core idea

```
source assets → layout/motion recipes → app working files → final exports
```

Portable source assets (images, copy, brand tokens, JSON specs) drive
ExtendScript (Photoshop, Illustrator, After Effects) and UXP (Premiere Pro)
automation. Each app produces a real, editable working file (`.psd`, `.ai`,
`.aep`, `.prproj`) and a real rendered export. Nothing here is a static
mockup — every export in this repo was generated by running the
corresponding script against the real, installed app.

## Honest status — what's real vs. what's a boundary

| App | Tier | Verdict |
|---|---|---|
| **Photoshop** | **A** | `do javascript file` via osascript, zero clicks. 5 real layered PSDs + PNG exports, all verified. |
| **Illustrator** | **A** | `do javascript` via osascript, zero clicks. Real vector `.ai` + PNG hang-tag design. |
| **After Effects** | **B** | No headless build hook — one deterministic GUI bootstrap (`Scripts/Startup/`), then scripted build + `aerender` headless render. Real 15s vertical MP4, verified. |
| **Premiere Pro** | **B** | Legacy ExtendScript is dead (sunsets September 2026 — confirmed via testing, not docs). Real platform is **UXP**: one-time dev-mode toggle, then a dropped plugin auto-loads forever. Proven live: real cut, real MP4 export straight out of Premiere via `EncoderManager.exportSequence()`. |
| **Lightroom** | **C** (confirmed, not assumed) | Installed product is Lightroom **CC**, not Classic — zero scripting surface (no AppleScript dictionary, no Lua SDK; that SDK is Classic-only). Adobe's cloud REST API is a real, untested Tier-A candidate gated on Developer Console credentials this environment doesn't have. |
| **Final Cut Pro** | n/a (interchange only) | No scriptable editing API at all (checked its `.sdef` directly). Real FCPXML timeline hand-off works and is the correct path — not a Premiere→FCP XML transfer, which is confirmed rejected by modern Final Cut. |

**What "Tier A/B/C" means:** A = agent does the whole normal workflow, zero
clicks. B = one deterministic one-time bootstrap, then fully scripted. C =
no real automation surface exists — confirmed by testing, not given up on
early. Full framework: this repo's automation choices follow an
agent-friendliness evaluation, not vibes.

## Known real bugs, fixed in this repo (not hidden)

- **Logo contrast bug:** the brand wordmark is navy-colored, invisible when
  pasted directly onto the navy banner background. Fixed by using cream
  text for the wordmark on dark backgrounds.
- **Missing headline layer:** the original promo banner spec never defined
  a headline layer at all — not a rendering bug, a spec omission. Fixed by
  rewriting the layout spec with real hierarchy.
- **Placeholder art used as if it were final art:** several exports used a
  crude vector shape (`accent_500x500.png`) as "product art" instead of the
  real product photography already present in the kit. Fixed by wiring the
  real photo through every export.

## What this proves

The recipe → app-file → export pattern is real and scriptable end-to-end for
Photoshop, Illustrator, and After Effects (Tier A/B), and — as of the
Premiere UXP work in this repo — for Premiere Pro too. Lightroom and Final
Cut's editing surface are honest, tested boundaries, not unexplored gaps.
